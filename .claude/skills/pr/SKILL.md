## 목적

구현·검증이 끝난 브랜치를 PR 로. 인자로 이슈 번호가 올 수 있다. 없으면 브랜치 이름·커밋 메시지의 `(#N)` 에서 찾는다.

## 사전 확인

1. `git status --short` — 커밋 안 된 변경이 있으면 목록을 보여 주고 멈춘다. 커밋은 사용자가 "커밋해줘"라고 할 때만 한다.
2. `git branch --show-current` 가 `dev` 나 `main` 이면 중단하고 브랜치를 먼저 만들자고 한다.
3. `git log dev..HEAD --oneline` 으로 PR 에 들어갈 커밋을 확인한다.
4. `/verify` 결과가 이 세션에 없으면 먼저 돌리거나, 사용자에게 검증 생략 여부를 묻는다.

## 본문 작성

기존 PR(#89, #96) 형식을 따른다. 스크래치패드 파일로 쓴 뒤 `--body-file`. 한국어. **저작권·생성 도구 표시 줄은 절대 넣지 않는다.**

```markdown
Closes #N

## 요약
무엇을 왜, 사용자 관점 2~4문장. 범위에서 뺀 것과 그 이슈 번호를 한 문장으로.

## 변경 사항
- **항목명** (`타입명`, 위치): 무엇을 어떻게. 설계 결정은 이유와 함께.
- **테스트**: 클래스 · 건수 · 무엇을 고정했는지. 등록한 테스트 타깃.
- 문자열 en 번역 N개, Info.plist · Logger 등 부수 변경.

## 확인
- [x] iOS 빌드(앱 + 위젯) · macOS 빌드 통과, 새 코드 컴파일 경고 없음
- [x] iOS 전체 단위 테스트 N건 통과 (새 M건 포함), macOS 테스트 타깃 통과
- [ ] 시뮬레이터: 화면·레이아웃 항목
- [ ] 실기기: 시나리오별 한 줄씩

## 참고
- 알려진 동작(의도된 로그, 플랫폼 제약)
- 범위 밖으로 넘긴 것과 이슈 번호
```

- "확인"에서 자동으로 검증한 것만 체크한다. 시뮬레이터로 못 본 화면과 실기기 항목은 미체크로 남긴다.
- 제목은 머지 대상 커밋 제목과 같게: `Feat: 한 줄 요약 (#N)`.

## 실행

```bash
git push -u origin <브랜치>
gh pr create --base dev --head <브랜치> --title '<제목>' --body-file <파일>
```

## 보고

PR URL, 베이스 → 헤드, `Closes #N` 포함 여부, 미체크로 남긴 확인 항목 수. 사용자가 실기기 확인 뒤 체크하면 된다고 한 줄.
